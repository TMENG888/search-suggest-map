# 联想异常诊断与验收

日期：2026-11-05；版本：2.4.1；Windows / Microsoft Edge。

## 实测原因

小红书关键词“react智能体框架详解pdf”在约1.7秒内返回 HTTP 200，但业务响应为 `code:3002, success:false, message:"方案执行结果为NULL"`，等待20秒也没有联想下拉。重新输入一次仍返回3002；同一浏览器接着查询起始词，正常返回10个衍生词。因此本例不能归因为页面未登录，也不能把3002当作确认没有下级词。

旧任务状态判断在错误文本中宽泛匹配“验证”，把“可验证下拉词”误识别成验证码。另一个解析问题是小红书实际成功响应使用 `code:1000, success:true`，旧解析器遗漏此结构，导致网络回执无法作为兜底。

## 修复行为

- 按明确错误类别区分验证码、登录、平台限制与联想结果未确认，取消普通报错中的“验证”子串判定。
- 接受小红书1000且success为true的成功结构；拒绝success为false的响应。失败响应不转换为空数组。
- 慢响应或失败回执仅允许一次正常重新输入，保持平台查询间隔；实际验证码和限制仍立即停止。
- 平台成功回执明确返回空数组时直接结束该分支，既不重试，也不要求产生非空衍生词。
- 两次都未确认的词保存为unconfirmed，不创建成功回执。其他可查询词继续，最终有遗留项则自动结束本轮并释放浏览器和运行锁，显示“已结束（有未确认词）”。不再进入等待人工重试的状态，也不声明所有分支完整展开。
- 待查词仅统计仍待启动和在途查询；无衍生词计入已完成，未确认词单独统计。结束后可下载结果包、编辑或启动其他任务；仅在用户主动重试时重新查询未确认词。
- 手动重试只处理未成功词；已成功回执继续复用。查询次数仍无限制，仅受递归层数约束。
- 每个平台保留最近一次异常的响应状态、耗时和输入框焦点诊断，供定位慢响应与访问异常。

## 验证

39项自动测试通过，包含延迟下拉恢复、失败恰好两次尝试、真假空结果、误判验证码、双平台空分支自动结束、异常词不阻断其他词、自动释放浏览器、其他任务可启动、仅重试失败词、旧等待状态迁移、断点重载、并发与原有任务操作。离线测试只证明控制逻辑。

完整GUI测试通过：结束状态不显示人工验证横幅，待查词为0，未确认数单独展示，新任务按钮可用，结果包可下载，可选重试成功后恢复完整完成；390px无横向溢出、无控制台错误。

2.4.1已在原双平台三层任务上验证自动收尾：102次成功查询、400个去重词、755条关系全部保留，其中1次查询明确返回空建议；另1个词仍未确认，独立保留且不创建虚假空结果。任务自动结束为partial，待查0，浏览器和运行槽已释放，结果包下载返回HTTP 200。本机回执保存在 `E:/Codex/outputs/20261105_空分支自动收尾/live-auto-finish-check.json`。
